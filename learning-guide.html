사진 인터랙티브로 배우는 JavaScript와 브라우저 AI

관찰 표시부터 모델 실행까지, 무엇을 직접 구현하고 언제 라이브러리를 사용할지 알아봅니다.

확인일: 2026년 10월 13일 · Transformers.js 공식 릴리스 및 npm 확인: 4.3.1

사진 인터랙티브로 돌아가기

배울 핵심은 두 가지입니다. 화면을 움직이는 JavaScript와 학습된 모델을 실행하는 Transformers.js는 함께 사용할 수 있지만, 담당하는 일이 다릅니다.

이 사진 페이지의 목표에는 내 관찰 표시 → 학습 단서 공개 → 비교·재검토가 직접 도움이 됩니다. 사물 인식 모델을 추가하는 것만으로 손·글자·빛의 오류나 진위를 판별할 수 있는 것은 아닙니다.

1. “요즘 JavaScript로 많은 것을 할 수 있다”는 말

맞는 말입니다. 발전한 것은 언어 문법뿐 아니라 브라우저의 그래픽·입력·계산 기능, 이를 묶는 라이브러리, 모델 실행 엔진입니다. 모델은 JavaScript 코드가 즉석에서 만들어 내는 것이 아니라, 이미 학습된 가중치를 내려받아 실행합니다. Hugging Face의 v4 공식 발표

도구의 종류하는 일이 사례의 사용
HTML·CSS·브라우저 API내용, 배치, 고정 사진, 입력 이벤트, 화면 갱신현재 페이지의 기반
Svelte 같은 화면 프레임워크화면 구성과 상태를 컴포넌트로 관리제공받은 NYT 저장 HTML에서 Svelte 구성 확인
시각화·애니메이션 라이브러리복잡한 차트나 긴 애니메이션 흐름을 편리하게 구성사진 한 장과 여섯 단계는 기본 API로 구현
Transformers.js텍스트·이미지 등의 학습된 모델을 로컬에서 추론이번 사진 페이지에는 사용하지 않음. 모델 실행을 배우는 별도 과제에 적합

인터랙티브의 동작 몇 가지를 재현할 수 있다는 것과 기사 전체가 초보 수준이라는 평가는 다릅니다. 제공된 저장 HTML에서 고정 배경, 확대·이동하는 장면, SVG 주석과 스크롤 텍스트를 확인했습니다. 제작자의 수준을 판단할 근거는 충분하지 않습니다.

2. 우리 페이지가 움직이는 순서

① 스크롤 읽기어느 설명이 화면에 가까운가?
② 단계 선택여섯 단서 중 하나를 선택
③ 사진 이동확대 배율과 사진 위치를 바꿈
④ 주석 표시SVG 테두리와 설명을 보여 줌

사진을 붙잡는 것은 CSS의 position: sticky입니다. transform으로 사진을 확대·이동하고, SVG로 같은 사진 좌표에 테두리를 그립니다. 스크롤 입력은 requestAnimationFrame으로 묶어 화면 갱신 시점에 읽습니다. CSS position · 화면 갱신 API

/* 화면에 사진을 유지 */
.story-visual {
  position: sticky;
  top: 0;
  height: 100svh;
}

/* 같은 사진을 다른 위치와 배율로 보여 줌 */
scene.style.transform =
  `translate3d(${x}px, ${y}px, 0) scale(${scale})`;

3. 클릭한 위치를 사진의 좌표로 바꾸기

확대한 사진에서도 같은 부분에 표시가 남아야 합니다. 클릭 위치를 화면 전체의 픽셀이 아니라 사진 안에서의 0~1 좌표로 저장하면, 화면 크기와 확대 배율이 바뀌어도 표시를 같은 곳에 그릴 수 있습니다. 마우스·터치·펜 입력에는 Pointer Events를 사용합니다.

const rect = imageWrap.getBoundingClientRect();
const x = (event.clientX - rect.left) / rect.width;
const y = (event.clientY - rect.top) / rect.height;

// x=0.5, y=0.5는 사진의 중앙.
// 사진 바깥을 누르면 저장하지 않음.
if (x >= 0 && x <= 1 && y >= 0 && y <= 1) {
  observations.push({ x, y });
}

우리 페이지의 “의심되는 곳 표시하기”는 이 원리를 사용합니다. 파란 점은 독자의 관찰, 노란 테두리는 미리 작성한 학습 주석입니다. “단서와 비교”의 숫자는 영역이 겹친 개수이며, AI 판별 성능이나 정답률이 아닙니다. 표시는 새로고침하면 지워집니다.

4. Transformers.js가 실제로 하는 일

지원되는 모델을 브라우저나 Node.js에서 실행할 수 있습니다. 브라우저에서는 ONNX Runtime과 WASM 또는 WebGPU를 이용합니다. 모델을 실행하는 별도 서버가 없어도 된다는 뜻이며, 첫 실행에 모델·실행 파일을 받아야 하는 경우가 일반적입니다. Node.js를 웹 서비스의 뒤쪽에서 실행하면 그 구성에는 서버가 있습니다. 공식 개요 · 파일 로딩과 ONNX 변환

Hugging Face의 모든 모델을 그대로 실행할 수 있는 것은 아닙니다. 지원 아키텍처와 변환된 가중치, 연산 지원, 기기 메모리를 확인해야 합니다. 양자화는 파일 크기와 계산량을 줄이는 방법이며, 수치 결과가 달라질 수 있으므로 연구에서 설정을 기록해야 합니다. WebGPU 안내

2026년 10월 13일 확인한 공식 최신 릴리스는 4.3.1입니다. 해당 릴리스는 EmbeddingGemma 2 지원을 추가했습니다. 새 모델이 지원된다는 사실이 우리 자료에서 가장 좋은 모델이라는 증거는 아닙니다. 4.3.1 릴리스

5. 사진에 바로 붙이지 않은 이유

시도무엇을 알 수 있나남는 문제
사물 인식사람·과일·그릇 같은 물체의 위치 후보실제 사건인지, 손의 접촉이 자연스러운지는 별도 판단
깊이 추정화면 안의 상대적 거리 예측예측 자체가 사진의 물리적 타당성 검증은 아님
사진 설명 생성그럴듯한 설명 문장가상 장면에도 설명이 생길 수 있음
내 관찰과 가이드 비교내가 본 위치와 안내 영역의 관계정답률을 주장하지 않고 직접 재검토 가능

이번에는 네 번째를 적용했습니다. 라이브러리를 더하는 것보다 학습자가 무엇을 살펴보고, 설명을 본 뒤 어떻게 다시 판단하는지에 초점을 맞췄습니다.

6. 다음에 배우기 좋은 모델 과제: 문장 검색

키워드가 달라도 비슷한 내용을 말하는 문장을 찾는 의미 검색은 별도 모델 실습으로 검토할 만합니다. 모델은 문장을 숫자 벡터로 바꾸고, 검색 프로그램은 벡터의 유사도를 계산해 후보를 정렬합니다. 마지막에는 사람이 원문을 읽어야 합니다.

가령 “세율 인하에 찬성한다”와 “세율 인하에 반대한다”는 같은 주제를 다룹니다. 내용이 비슷하다는 점수만으로 입장이 같다고 판단하면 안 됩니다. 모델의 역할은 검토 후보를 줄이는 데 있습니다.

실습을 시작할 때 참고할 코드 — 이 페이지에서는 실행하지 않음

별도의 Node.js 또는 모듈 개발 환경에서 라이브러리를 4.3.1로 고정해 설치한 뒤 사용하는 예시입니다. 모델 다운로드도 필요합니다. 이 코드의 연구 자료 성능은 검증하지 않았습니다. 모델과 라이브러리 버전을 고정하고, 원문은 보존하세요.

import { pipeline } from '@huggingface/transformers';

const embed = await pipeline(
  'feature-extraction',
  'Xenova/multilingual-e5-small',
  {
    device: 'wasm',
    dtype: 'q8',
    revision: '761b726dd34fb83930e26aab4e9ac3899aa1fa78'
  }
);

const vectors = await embed([
  'query: 세율을 낮춰야 한다는 의견',
  'passage: 세금 부담을 줄이는 방안이 필요하다.',
  'passage: 현재 세율을 유지해야 한다.'
], { pooling: 'mean', normalize: true });

const [question, ...documents] = vectors.tolist();
const scores = documents.map((v, i) => ({
  candidate: i + 1,
  similarity: v.reduce((sum, x, j) => sum + x * question[j], 0)
}));
console.table(scores);

// 유사도는 후보 순서를 만들기 위한 값.
// 찬성·반대의 확정 판정은 별도 검토가 필요함.

이 예시 모델은 ONNX 배포본이 있으며, 원 모델 안내는 검색 질의에 query:, 문서에 passage: 접두어를 요구합니다. 긴 입력은 512토큰에서 잘릴 수 있어 문장·문단 단위 설계를 따로 해야 합니다. ONNX 배포본 · 원 모델 안내
